# Atividade Avaliativa — Testes Não Funcionais

## Sistema Bancário

### Objetivo

Avaliar aspectos não funcionais de um sistema bancário, principalmente relacionados à **usabilidade**, facilidade de utilização e experiência do usuário.

---

## 1. Cite 5 pontos que você exploraria livremente no sistema

Durante uma exploração livre do sistema bancário, eu verificaria os seguintes pontos:

### 1. Login e autenticação

Testaria a facilidade para realizar login, recuperação de senha, mensagens de erro, validação dos dados e comportamento do sistema após várias tentativas de acesso.

### 2. Consulta de saldo e extrato

Verificaria se o usuário consegue encontrar facilmente seu saldo, consultar o extrato e identificar informações como data, valor e descrição das movimentações.

### 3. Transferências bancárias

Exploraria o processo de transferência, verificando se as informações são apresentadas de forma clara, se os campos são fáceis de preencher e se existe uma confirmação antes de concluir a operação.

### 4. Pagamento de contas

Testaria a facilidade para localizar a função de pagamentos, inserir os dados necessários e confirmar a operação.

### 5. Navegação e organização das funcionalidades

Exploraria os menus e telas do sistema para verificar se as principais funcionalidades estão organizadas de maneira intuitiva e se o usuário consegue encontrar rapidamente o que precisa.

---

## 2. Cite 5 possíveis problemas de usabilidade que poderiam existir

### 1. Menus confusos

O sistema pode apresentar muitas opções ou utilizar nomes pouco claros para suas funcionalidades.

### 2. Mensagens de erro pouco explicativas

O sistema pode apresentar mensagens como "Erro 400" ou "Operação inválida" sem explicar ao usuário o que aconteceu ou como resolver o problema.

### 3. Processo de transferência muito complexo

Uma transferência pode exigir muitas etapas, informações desnecessárias ou apresentar telas confusas antes da confirmação.

### 4. Falta de confirmação das operações

O sistema pode não apresentar uma confirmação clara antes ou depois de operações importantes, como transferências e pagamentos.

### 5. Interface pouco acessível

O sistema pode utilizar fontes pequenas, baixo contraste, botões difíceis de identificar ou elementos que não funcionam adequadamente em dispositivos móveis.

---

## 3. Explique por que esses problemas impactam o usuário

Os problemas de usabilidade podem afetar diretamente a experiência do usuário e, em um sistema bancário, podem gerar consequências ainda mais graves.

### Menus confusos

Menus mal organizados fazem com que o usuário tenha dificuldade para encontrar as funcionalidades desejadas. Isso aumenta o tempo necessário para realizar tarefas e pode causar frustração.

### Mensagens de erro pouco explicativas

Mensagens de erro que não explicam o problema deixam o usuário sem saber o que fazer. Isso pode levar a tentativas repetidas ou até ao abandono da operação.

### Processo de transferência complexo

Uma transferência com muitas etapas aumenta a possibilidade de o usuário cometer erros ao preencher os dados. Em um sistema bancário, isso pode ser especialmente problemático porque envolve movimentação de dinheiro.

### Falta de confirmação das operações

A ausência de uma confirmação clara pode gerar insegurança. O usuário pode não saber se uma transferência ou pagamento foi realmente concluído e pode tentar realizar a mesma operação novamente.

### Interface pouco acessível

Uma interface com problemas de acessibilidade pode dificultar ou até impedir que determinados usuários utilizem o sistema corretamente. Além disso, uma interface inadequada em dispositivos móveis prejudica a experiência de quem acessa o banco pelo celular.

---

## Conclusão

Os testes não funcionais de **usabilidade** são muito importantes em sistemas bancários, pois não basta que o sistema funcione corretamente. Ele também precisa ser **fácil de entender, seguro, acessível e intuitivo**.

Problemas de usabilidade podem aumentar a quantidade de erros cometidos pelos usuários, gerar insegurança durante operações financeiras e causar uma experiência negativa.

Por isso, durante os testes, é importante avaliar não apenas se as funcionalidades estão funcionando, mas também **como o usuário interage com o sistema para realizar suas tarefas**.
